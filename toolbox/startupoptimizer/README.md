# OrCAD 启动优化工具

双击 `dist/OrCAD启动优化工具.exe`，无需安装 Python 或开发环境；使用 Windows 的 .NET Framework 4.x。

1. 自动识别本机 OrCAD；也可选择 SPB 安装目录或 `tools/capture/tclscripts/capAutoLoad`。
2. 选择方案，查看各功能停用后的影响。勾选代表准备停用。
3. 保存工程并退出所有 Capture 窗口，点击“备份并停用所选”。
4. 重新启动 Capture。需要恢复时关闭 Capture，点击“恢复本工具停用项”。

保守方案只选择示例浏览器和学习资源。它们主要注册菜单，提速可能很小。“不用建模助手”额外选择 27 个 PSpice 模型助手脚本；使用模型创建或专用编辑功能时请保留。云元件库、OrCAD 欢迎页需要按需勾选。清空勾选不等于恢复。

按本机 OrCAD 17.4 脚本内容整理白名单。只管理列出的 31 个可选脚本，不提供批量禁用未知脚本的入口。DRC、保存、PCB 联动、PSpice 核心、BOM 和立创等自定义插件不在停用名单内。其他版本的兼容性尚未验证。

备份位于 `capAutoLoad` 的同级目录 `xiaokai-startup-backup`，不放在自动加载目录内，也不修改脚本正文。备份保留原始字节和 SHA-256；每次删除前先持久化备份清单。正常异常会尝试回滚，进程意外中断后可用恢复按钮继续。恢复不会覆盖内容不同的现存脚本。恢复成功后仍保留历史备份文件，清单只记录尚需恢复的项目。不要在仍有停用项时删除备份目录。

安装目录只读时，右键 EXE 选择“以管理员身份运行”。程序不会自动提权，也不会关闭 Capture 进程。扫描和导出报告不改动安装目录。

重新统计原始日志共有 104 个 Loading 项，但没有各项耗时，因此不承诺固定提速幅度。可在同一工程、相同网络条件下，分别记录原状态和优化后从启动到可操作的时间，各测 3 次比较。保守方案收益不明显时，可按使用情况尝试停用欢迎页和建模助手；许可证等待、网络盘及工程大小也可能影响启动。

开发构建：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File startupoptimizer/build.ps1 -Test
```

测试使用隔离的临时目录，覆盖原始字节恢复、重复操作、运行中拦截、更新冲突、损坏备份、中途失败回滚、恢复中断重试及写入互斥。尚需在实际 Capture 中验证停用后的菜单和启动体验。
